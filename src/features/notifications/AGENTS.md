# Notifications — AGENTS.md

"An event happened and someone should hear about it", as one data model for
self-hosted, High Availability and the store apps (decided 2026-09-18).

| File | Owns |
| --- | --- |
| `events.ts` | The catalogue: event codes, severity, scope, and the sentence each renders. **Only events with an emitter are listed** — add the code and the emitter in one commit. `NOTIFICATION_EVENTS` / `NOTIFICATION_RULE_EVENTS` / `NOTIFICATION_SEVERITIES` are pinned to the CHECKs in `schema.ts` by `src/db/enum-checks.test.ts`. |
| `records.ts` | The four tables (`channel`, `rule`, `notification`, `attempt` — created as `notification_*` in `0002_notifications` and renamed to single words in `0003` per the table-naming rule, which now folds `RENAME TO` in journal order). A channel `address` is a sealed `tpsecret` for every kind but `email`; `signing_secret` always is; both are a stage of the re-encrypt sweep (`notifications`, before `authproviders`). Vocabularies for scope / kind / delivery status live here. |
| `emit.ts` | `emitNotification` — fan-out and delivery, **never throws**. Inbox rows for every organization member (or every instance admin for an instance-scoped event); one `notification_delivery` row per routed channel, written before the send; one bounded attempt inline; `retryDueDeliveries` on both maintenance ticks (Workers `notification-retries` phase, Deno cleanup) with backoff 1/5/25/125 min and a cap of 5. An email channel's delivery is one `notification` job on the mail queue when the emitter was given one (`deps.email`: queue, from, console base URL — the Deno sweep and the request context pass theirs, the Workers cron resolves them per tick); push rows are left `pending` for the Expo transport. |
| `senders.ts` | One bounded, never-rejecting POST per kind: generic webhook (JSON body + `X-TurboPanel-Event` + HMAC `X-TurboPanel-Signature: sha256=…` over the raw body when the channel has a signing secret), Slack (`text`), Discord (`content`), Telegram (Bot API, address `<token>/<chat id>`). Errors are short codes or `http_<status>`, never the address or a body. |
| `audit-bridge.ts` | `recordAuditAndNotify` — the emitters for audit actions a teammate wants to hear about (`AUDIT_EVENTS`); the routes call it where they called `recordAudit`. |

Rules:

- **Routing scope.** An organization event reaches the organization's channels, its members' user channels and every instance channel; an instance event reaches instance channels only. A rule row is required for any channel (`*` or one code, with a severity floor); the inbox needs none.
- **Inbox audience** (`events.ts` `audience`, decided 2026-09-18): `members` — every teammate of the organization (`server.offline`); `managers` — holders of `organization:own` / `organization:manage` plus instance admins, for the events that mirror the owner-only audit trail (deletes, key revokes, grant changes). A plain teammate never learns a grant change from the bell.
- **Email addresses are delivered to only once known** (`channel.verified_at`, decided 2026-09-18): the create route accepts the caller's own address for a personal channel and any member's account email for an organization channel, and stamps `verified_at`; anything else is **422** `address_not_a_member` until a verification flow exists. `deliverableHere` skips an unverified email channel, so a row written by another path stays `pending`.
- **No double send.** A fresh `attempt` row carries `next_attempt_at = now + 2 min` (`INLINE_ATTEMPT_GRACE_MS`), so the 60-second retry sweep only reaches a row whose inline attempt never recorded itself; `attempts` is bumped in SQL, never read-then-written.
- **Not built, named so the rows stay honest:** digest / quiet hours on rules, an email verification flow for stranger addresses, a console screen for instance channels (API only today), push.
- **Addresses are re-validated at send** through `outbound-url.ts`; the self-hosted runtime passes `allowPrivateTargets: true` (a LAN Alertmanager is legitimate there, decided 2026-09-18), hosted never does. Telegram is exempt — its host is `api.telegram.org`.
- **The operator's webhook is an instance channel** (`OPERATOR_WEBHOOK_LABEL`, kind `webhook`, rule `*` at info). The legacy `ALERT_WEBHOOK_URL` setting is adopted into it on first touch (`adoptLegacyAlertWebhook` — from the admin routes and from `resolveAlertSender` per tick) and the row deleted; `PUT /api/admin/v1/settings/alert-webhook` is a thin face over that channel so the documented curl keeps working. Instance channels are managed at `/api/admin/v1/notification-channels` (`src/admin/notification-routes.ts`); an instance email channel may name any administrator's account email.
- Workers-bundle safe: no `@std/*`, no `fetch` / `crypto` at module load.
- Tests: `events.hostfree.test.ts`, `senders.hostfree.test.ts` (pure), `emit.test.ts` (real Postgres, skipped without `TURBOPANEL_DATABASE_URL`) — all three in `scripts/test-coverage.sh`.
